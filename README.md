## Запуск в VS Code

1. Открыть эту папку в VS Code.
2. Выполнить `Dev Containers: Reopen in Container` через палитру команд.
3. Дождаться создания Debian-контейнера. Открыть его терминал.
4. Выполнить `chmod +x run.sh scripts/*.sh` и затем `./run.sh`.

Дерево создаётся строго в `~/lab0`, а журналы — в папке `evidence` рядом со скриптами.
Если `~/lab0` существует, скрипт остановится без удаления предыдущих данных.
Для снимков экрана можно открыть логи командой `less evidence/01_create.log`
и аналогично для последующих этапов. Делать скриншоты следует из реального VS Code.

Скрипты 01–04 используют разрешённые команды задания. Обвязка `run.sh`
использует встроенные средства Bash для проверки условий и организации запуска.
Каждая ошибка останавливает выполнение. Последующий этап не запускается при ошибке.
Создаются три локальных коммита в `~/lab0`.

## Публикация результатов

Исходники находятся в ветке `main`. Результаты выполнения публикуются
отдельной веткой `execution`, чтобы не перезаписать исходники:

```bash
cd ~/lab0
git remote add origin https://github.com/bald-monkey-perapinak/lab1.git
git push -u origin execution
```

Настройка remote относится к подготовке Git; команда публикации соответствует заданию.
Git сохраняет содержимое, символические ссылки и признак исполняемости.
Он не сохраняет полные права Unix, пустые каталоги и отношения жёстких ссылок.
Поэтому проверять эти свойства нужно в контейнере по `ls -lRi` до удаления ссылок.
